# Banco no Supabase (etapa 3): plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A vitrine passa a ler categorias, peças, kits e configurações do Supabase (projeto `cardoso-menswear`, São Paulo), com esquema, regras de acesso e bucket de fotos versionados como migrações, e a conferência ao enviar o pedido lendo o banco de verdade.

**Architecture:** Migrações SQL em `supabase/migrations/` chegam ao banco pela integração do Supabase com o GitHub. O app ganha uma `FonteVitrine` do Supabase (`supabase-js` com a chave publicável) que monta a mesma `Vitrine` da etapa 1; as telas não mudam. Sem as variáveis de ambiente, o app continua usando o JSON de exemplo (testes e desenvolvimento offline).

**Tech Stack:** o da etapa 1 e 2, mais `@supabase/supabase-js` e a CLI do Supabase via `npx supabase` (só para `init` e para gerar arquivos; sem login, sem Docker).

**Spec:** `docs/superpowers/specs/2026-11-05-vitrine-pedidos-design.md` (seções "Banco de dados", "Preços e conferência", "Estrutura e publicação"). Plano anterior: `docs/superpowers/plans/2026-11-05-vitrine-e-sacola.md`.

### Task 3: Segurança e fotos

**Files:**
- Create: `supabase/migrations/20261105120100_seguranca.sql`, `supabase/migrations/20261105120200_fotos.sql`
- Modify: `src/integracao/migracoes.test.ts`

**Interfaces:**
- Produces: `private.is_admin() returns boolean` — `language sql stable security definer set search_path = ''`, corpo `select exists (select 1 from public.admins where user_id = (select auth.uid()))`. Schema `private` criado aqui, sem `usage` para `anon`; `grant usage on schema private to authenticated` e `grant execute on function private.is_admin() to authenticated`; `revoke execute … from public, anon`.
- Grants: `grant select on` todas as tabelas de leitura pública `to anon, authenticated`; `grant insert, update, delete on` todas, menos `admins`, `to authenticated` (a política decide). `admins`: nenhum grant para `anon`; `select` para `authenticated`.
- Políticas (todas com `(select private.is_admin())` envolto em `select`, para rodar uma vez por consulta):

| Tabela | Leitura (`anon, authenticated`) | Escrita (`authenticated`) |
|---|---|---|
| `categorias` | `visivel or (select private.is_admin())` | `is_admin()` |
| `pecas` | `(not arquivada and exists (select 1 from public.categorias c where c.id = categoria_id and c.visivel)) or is_admin()` | `is_admin()` |
| `peca_fotos`, `peca_tamanhos` | `exists (select 1 from public.pecas p where p.id = peca_id)` (a RLS de `pecas` já filtra) `or is_admin()` | `is_admin()` |
| `kits` | `publicado or is_admin()` | `is_admin()` |
| `kit_pecas` | `exists (select 1 from public.kits k where k.id = kit_id)` (idem) `or is_admin()` | `is_admin()` |
| `configuracoes` | `true` | `update` só, `is_admin()` |
| `admins` | `user_id = (select auth.uid())` | nenhuma (só pelo painel do Supabase) |

  Escrita = uma política por comando (`insert` com `with check`, `update` com `using` e `with check`, `delete` com `using`).
- Fotos: `insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types) values ('vitrine', 'vitrine', true, 5242880, array['image/webp','image/jpeg','image/png'])`; políticas em `storage.objects` para `insert`, `update`, `delete` `to authenticated` com `bucket_id = 'vitrine' and (select private.is_admin())`. Sem política de `select`: bucket público serve a URL pública.

- [ ] **Step 1:** Acrescentar ao teste: todo `create table public.<t>` tem um `alter table public.<t> enable row level security` em algum arquivo → `npm test` → FAIL (tabelas sem RLS). Acrescentar também: todo `create policy` usa `(select private.is_admin())` em vez de `private.is_admin()` solto, e `auth.uid()` só aparece como `(select auth.uid())`.
- [ ] **Step 2:** Escrever as duas migrações → `npm test` → PASS.
- [ ] **Step 3: Commit** `"Adiciona as regras de acesso e o bucket de fotos"`

### Task 5: Fonte da vitrine no Supabase

**Files:**
- Create: `src/vitrine/fonteSupabase.ts`, `src/vitrine/fonteSupabase.test.ts`

**Interfaces:**
- Consumes: tipos de `src/vitrine/tipos.ts`; `paraCentavos` (`src/lib/dinheiro.ts`).
- Produces:

```ts
type Linhas = {
  categorias: { id: string; nome: string; slug: string; grade: string[]; ordem: number }[];
  pecas: { id: string; slug: string; nome: string; descricao: string | null; categoria_id: string; preco: number | string; criado_em: string;
           peca_fotos: { path: string; ordem: number }[]; peca_tamanhos: { tamanho: string; disponivel: boolean }[] }[];
  kits: { id: string; slug: string; titulo: string; descricao: string | null; foto_path: string | null; ordem: number;
          kit_pecas: { peca_id: string; ordem: number }[] }[];
  configuracoes: { loja_aberta: boolean; whatsapp_numero: string; instagram_url: string; grupo_whatsapp_url: string; texto_entrega: string };
};
function urlDaFoto(path: string, urlBase: string): string; // "/x.jpg" fica igual; "pecas/a.webp" → `${urlBase}/storage/v1/object/public/vitrine/pecas/a.webp`
function montarVitrine(l: Linhas, urlBase: string): Vitrine;
function criarFonteSupabase(cliente: SupabaseClient, urlBase: string): FonteVitrine;
```

  `criarFonteSupabase().carregar()` faz as 4 consultas em paralelo (`categorias` ordenada por `ordem`; `pecas` com `peca_fotos(path, ordem)` e `peca_tamanhos(tamanho, disponivel)`; `kits` com `kit_pecas(peca_id, ordem)`; `configuracoes` com `.single()`) e **rejeita** se qualquer uma devolver `error` ou se `configuracoes` vier vazia. Fotos e peças do kit ordenadas por `ordem` em `montarVitrine`. Kit sem `foto_path` usa a primeira foto da primeira peça. `descricao` nula vira `''`.
